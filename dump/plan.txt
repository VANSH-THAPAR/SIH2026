## The implementation rule I would lock in

**Frontend first, but API-shaped from day one.**

```text
              NOW
               │
               ▼
        ┌───────────────┐
        │ React Frontend│
        │               │
        │ VERY RICH     │
        │ VERY INTERACTIVE
        └───────┬───────┘
                │
                ▼
          Basic FastAPI
                │
                ▼
             NeonDB
                │
                ▼
          report_analysis
```

Then progressively upgrade the backend:

```text
Basic CRUD
    ↓
AI Analysis
    ↓
Safety Engine
    ↓
Vector Search
    ↓
Pattern Engine
    ↓
Risk Engine
```

That approach gets you to a **convincing working product quickly**, while leaving room to add the genuinely intelligent parts without rebuilding the frontend every time the backend grows a new brain.
